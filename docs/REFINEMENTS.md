# AyuGram: Standard and Custom

Both variants use the same audited Swiftgram source and common patches 01–05, 07, 08, 10, 11, 13 and 14, with a variant-specific settings patch 12. Custom additionally applies patches 06 and 09. GitHub Actions starts two independent, concurrent full iPhone arm64 builds. A failure of one job does not cancel the other.

## Common changes

- Local root-chat pins use a keyed Postbox Codable object. A top-level Int64 array was encoded as Int64Array and never read by PreferencesEntry.get, which only decodes Object. The local list previously disappeared from the application's perspective and it reverted to Telegram's 5/10 pin limit. Pins remain device-local after increasing the slider.
- Real Telegram Premium accounts preserve native custom emoji when sending. Non-Premium accounts with Local Premium send the ordinary emoji text without paid entities or generated pack links. Explicit user-authored links and other formatting remain intact.
- The sender's animation is stored as local message metadata, preserved on delivery and matching-text server refreshes, and excluded from outgoing entity serialization. Recipients see ordinary emoji; a message edit with different text drops an obsolete overlay. Older marker messages remain readable, but new messages no longer create markers or previews. Shared Premium/status profiles remain separate from this local message animation.
- Emoji packs and emoji search honour Local Premium. Premium stickers and other paid server entitlements are unchanged.
- Non-Premium local emoji statuses persist separately by account and survive subsequent Telegram peer updates. Native peer serialization and paid-account status changes continue using the actual server status.
- Message History has per-account chat selection using the native folder-style multiselection controller and search. Collection starts only after choosing chats. Already cached ordinary photos are copied before the deletion update removes their cache resource. Secret, disappearing and copy-protected messages are excluded. Uncached photos cannot be recovered.
- Remote deletions preserve selected, already received ordinary messages at their original ID and timestamp with a local trash marker. The Postbox deletion flag preserves the incoming direction while excluding these messages from unread counts; normal local deletion remains available. Repeated server deletion updates do not decrement thread statistics repeatedly. Stale refreshes cannot resurrect a retained deletion.
- Edited messages show a collapsible original-message quote in the bubble. The message menu opens its complete captured edit history. The rendered quote does not alter the network message text or its entities; reply-quote selection is disabled on this local annotation.
- History displays message cards with the changed text, previous version, author/profile action, source-chat action, photo previews, video playback and document previews. Author IDs and original timestamps are saved for new entries; older text-only archives remain readable.
- History remains bounded to 200 entries and 30 days, with a 200 MB archive budget and 20 MB per archived item. Cached ordinary photos, video and files are copied; unavailable media cannot be recovered. Pruning and clearing also remove retained deleted messages and archive files.
- New labels, old privacy menus, server presence and receipt actions/confirmations follow the selected app language. AyuGram translations are bundled for all 37 Swiftgram locales; unsupported third-party language codes use the existing English fallback. Telegram's native picker/action strings use its language pack.
- The gallery shows a themed View button above its controls for an unconsumed disappearing photo opened privately. Confirming sends the view receipt and starts its expiry; a failed request leaves the action available. The button resolves the original Postbox message rather than relying on the temporary display copy.
- Successfully sending a message acknowledges previous messages in that same chat, even with Anti Read enabled. The delivery callback uses the confirmed cloud message ID; failed sends, scheduled/quick-reply namespaces and Saved Messages are excluded. This does not report consumption of unopened photos or voice messages.
- The application name and top pill use AyuGram branding. The main settings retain a separate Swiftgram row for the original Swiftgram options, followed by an AyuGram row with the purple plane icon for this client's options. The native Privacy and Security row remains separate.
- The three user-supplied icons are available in Appearance. Icon selection is saved locally and drives both the settings selection and the top pill across page changes and restarts. The client also requests the native Home Screen icon change and reports an iOS refusal without discarding the local selection. Container-hosted installations may require configuring their Home Screen icon in the host separately.
- A separate purple plane owner badge is displayed for immutable Telegram user ID 1272887902 (@distressedx2x) after the Premium/status icon in profile, chat header, chat list and message author headers. Names remain unchanged. The top pill draws a foreground plane over a stretched dark plane watermark using the selected icon colour.

## Custom only

Appearance uses native Swiftgram grouped rows and pushed navigation with a back button. Switches, sliders and actions follow the current theme. A live preview shows the selected photo/video with its current effects and sample text. Sliders expose their actual bounds: dimming 20–90%, blur 0–100% and chat row opacity 35–100%.

The chat list and conversation wallpaper have separate media, dimming, blur and motion settings. Existing installations keep their previous shared background in both places until changing one scope. Replacing or resetting either scope preserves the other scope's file. Conversation customization is also accessible through the native Appearance → Wallpapers page. The first list photo/video is inherited by the conversation until a separate wallpaper is selected. Empty wallpaper overrides from build 21 inherit the list media instead of hiding it. Explicitly resetting conversation customization restores the native Telegram wallpaper. The native header edge effect is hidden only when a custom list background is active outside search.

Pinned and ordinary chat rows use the same backdrop opacity. Embedded message rows, including the profile's personal-channel card, retain their native transparent background. Changing a setting refreshes existing list rows immediately, including when the presentation theme has not changed.

Video is muted and pauses when detached, in the background, with Reduce Motion or with Low Power Mode. A still frame remains visible when motion is disabled. The first video frame and downsampled photo are prepared off the main thread; images are limited to 1536 pixels for the background renderer. Media stays inside the application container and is excluded from cloud backup. Imports are limited to 100 MB.

## Automatic client badges

Client badges use a separate automatic registry without bot authentication. Only the public Telegram ID is registered; recently visible IDs are looked up in batches. Other updated AyuGram clients can display member badges. Fake Premium and fake emoji status remain local. See SHARED-PROFILES.md for the protocol and its limits.

## Validation

Local validation checks patch application from the exact base commit, changed Swift syntax against original sources, native string references, all 37 locale dictionaries, workflow matrix and CI helper tests. Each native build parses all final changed Swift sources, tests archive migration, unread/direction flags, path containment, record cap and expiry, and typechecks the badge, archive cards and media viewers against the actual iOS 13 SDK. Custom additionally checks the real picker/playback/preview APIs against the minimum iOS SDK and runs isolated Foundation tests for background migration, independent imports/resets, range bounds, persistence and media cleanup. It then generates the full project and builds the complete app with Bazel. Artifact verification checks alternate icon references and the 120/180-pixel PNG assets, including Apple-optimized PNG headers. Successful compilation does not establish device behaviour; the reported runtime bugs still need verification on an iPhone.

Artifacts: `AyuGram-standard-unsigned.ipa` and `AyuGram-custom-unsigned.ipa`. They use the configured bundle identifier and are alternative versions of the same app. They require signing/import into the user's installation setup.

Video wallpapers use a video-only composition in both scopes. Audio tracks are never passed to AVPlayer, external playback is disabled and wallpaper playback never configures or activates AVAudioSession. A native fixture verifies that video duration and orientation survive removal of an actual audio track. Device checks with music playing remain necessary.

## Ghost Mode, content and settings (patches 24–26)

- The AyuGram screen was redesigned: a summary card shows the Ghost Mode state and how many signals are hidden, followed by grouped sections with Settings-style icons and explanations — Ghost Mode, what to hide, behaviour, content, history and client. All new labels are bundled for the 37 Swiftgram locales.
- Ghost Mode: while online status is hidden, a delivered message is followed by `account.updateStatus(offline)` because the server marks the sender online on activity (Offline after sending, on by default). Reading a chat after replying is now a switch (Read chat when replying, on by default — the previous behaviour). Long-pressing the Chats tab offers Enable/Disable Ghost Mode with a confirmation toast; individual switches keep their values.
- Content protection (Ignore content protection, on by default): protected chats and messages behave like ordinary ones for saving to the gallery, copying text, sharing and forwarding. The server rejects forwarding and reusing protected media references, so such forwards are sent as copies without the author: text and entities are copied and photos/files are downloaded and uploaded again (stickers reuse their public documents; contacts and static locations are copied). Albums stay grouped. A source that cannot be copied keeps its original forward request.
- Screenshots (Allow screenshots, on by default): the secure-layer screenshot protection and `preventsCapture` on video layers are disabled. The setting applies to newly opened screens. Secret chats still send their native screenshot notification.
- Custom: video wallpapers are decoded with AVAssetReader and shown through AVSampleBufferDisplayLayer instead of AVPlayer. AVPlayer activates the shared audio session even when muted and without an audio track, which stopped music in chats, the chat list and the appearance preview. Background labels in Appearance now use dedicated translations.
- Settings → Edit: the help text under Add Another Account states the actual Swiftgram limit of 500 accounts instead of Telegram's 3/4 (patch 27).
- Edit history no longer records reactions, view counters or refreshed file references as edits: only changed text or a replaced photo/file counts. An original-message quote identical to the current text is never shown, which also hides markers created by earlier builds (patch 28).
- Custom: the chat list row shade is applied by the background to the whole screen, so the header and the rows have the same darkness; rows themselves stay transparent except the selected one. Wallpaper video decoding is limited to three frames per tick and resynchronises instead of decoding a burst when it falls behind (patch 29).
- Custom: the wallpaper video layer is only changed on the main thread; decoding stays in the background. Background layer updates outside a committed transaction could stall chat updates, leaving conversations on the loading placeholder while a custom background was shown (patch 30).
- Ghost Mode no longer stalls the app. Reads made while receipts are hidden stay local, so the server's read position is behind; read-state validation answered that with an immediate retry, restarting forever per chat, flooding getPeerDialogs and the state manager queue so chats and the chat list stopped loading. Validation now keeps the local read state and stops, and any read-state retry waits one second (patch 31).
- Message history is redesigned: a summary card with All / Deleted / Edited counters that also act as filters, records grouped by day, cards with an initials avatar, a coloured Deleted/Edited label, tinted before/now quotes, inline photo and video previews and a Show in chat button, an empty state that offers to add chats, and tracked chats listed with avatars and record counts (tap to open or stop saving). Nine new strings in all 37 languages (patch 32).
- Sideloaded installs start. Signing tools usually drop the `group.<bundle id>` app group, so the app group container was missing and Telegram stopped at launch with "Error 2" (LiveContainer worked because it provides its own container). The main app now falls back to a private Library directory when the app group is unavailable; the background upload session only names the shared container when it exists. Extensions keep their existing behaviour (patch 33).
- All six app extensions (Share, notification content and service, Siri intents, widget, screen broadcast) are kept and now work after sideloading: CI ad-hoc signs every extension and the app with its application identifier and the shared `group.<bundle id>` app group, which re-signing tools read to register the group. CI fails if any extension is missing from the IPA. Swiftgram's action extension stays off: its source is commented out upstream and would crash.
- Message history (patch 34): deleted messages now stay in every chat while Save Deleted Messages is on; only the chats chosen in Message history are also listed there. Photos, GIFs, videos and pictures sent as files in those chats are downloaded as soon as they arrive (up to 20 MB), so a deleted message keeps its media even if the chat was never opened, and cards preview them inline (GIFs with a GIF badge). Cards show the real profile photo of the author or chat, including a personal photo you set for a contact, with initials while it loads. The Include Chats picker preselects chats once: passing them again as initial peers toggled each chat a second time, duplicating and leaving stale tokens.
